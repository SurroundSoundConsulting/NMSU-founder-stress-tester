# Resume only the missing work

Read the ledger/manifests, current sources and authority, the same registered Doc and complete comments. Preserve every known Doc/thread/reply ID, immutable plan and original method. Confirm current sources and feedback version before any continuation. Recovery starts with inspection, not another edit or reply.

| Saved state | Next action |
| --- | --- |
| Partial plan/chunk save | Complete only known exact missing records under the existing IDs; no Doc effect until the entire manifest is verified. Missing or conflicting bytes stop. |
| Plan saved, no effect intent | Recheck current evidence and target. Save/read back the exact effect intent before publication. |
| Edit intent, response unknown | Compare full current native state with exact before and expected-after. Inspect threads before retrying. |
| Exact expected-after | Save edit verification and continue only the missing reply/final records. Zero repeated edits. |
| Exact original before state and original revision | A recorded human decision naming item/operation, actor/time/reason may authorize the same guarded batch. A missing result alone is insufficient. |
| Same original text but newer revision, different content/style, partial effect or unreadable Doc | Preserve current work; record needs_reconciliation. Do not overwrite or roll back human changes. |
| Edit verified, reply not attempted | Reconstruct the saved actual change and original thread; recheck complete replies, save reply intent, then publish only the missing reply. |
| Reply intent, unknown outcome/no returned ID | Search the complete original thread and marker inventory. An exact unique reply may supply the actual native ID. Missing marker/empty discovery never authorizes automatic resend. |
| Reply ID known | Inspect that exact ID and parent. Missing/deleted/changed reply stops; do not post a replacement automatically. |
| Reply verified, final Sheet save missing | Save final records only. Zero edits or replies. |
| Complete | Return the same registered Doc/item/thread/reply and original completion time read-only. Label changed inputs/outputs; leave history intact. |

Matching a reply requires the exact saved content, operation marker, native ID when known and original parent thread. Duplicate markers, wrong parent, an extra human reply, edited source feedback, incomplete inventory or resolved/deleted thread stops automatic recovery. A wrong-thread reply is a failed effect requiring an explicit bounded repair decision; preserve evidence and do not silently delete or resolve human threads.

Before every recovery effect, verify source versions, author grant, selected post, conflict state and writer again. Changed business inputs require a new decision. A person accepting/rejecting an existing suggestion is a separate observed decision, never permission to redo the proposal or mark a task done.

An uncertain Sheet append is inspected by exact event ID and predecessor before retrying. An identical saved row is reused; duplicate/conflicting IDs stop. Sheet unavailability stops further external effects; explain that the durable result could not be saved. Previously saved intent blocks a fresh run from assuming nothing happened.

A request name, newer skill, elapsed timeout or copied workbook does not release an uncertain writer. Explicit closure retains all known effects and requires a human reconciliation decision if an edit/reply was attempted. Single-writer operation is not atomic locking and no transaction spans Docs and Sheets.

Denied operations remain denied. Inspect read-only, preserve the denial and request a concrete authorized continuation when needed. Never switch tools, accounts, encodings or identities to bypass review. No browser fallback is implemented by this method.
