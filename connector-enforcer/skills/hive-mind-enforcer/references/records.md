# Persistent records and ownership

Use existing hidden `Executor Connector` columns unchanged:

This is the legacy connector ledger adapter, preserved for historical reconstruction. If the selected V2 instance configures `Work Enforcer`, `Work Enforcer Log` and `Work Enforcer Reviews`, inspect those actual schemas and map the logical records below to their configured locations. Keep existing records and ownership; loading this package does not create tabs, migrate state or authorize a new writer. The optional JavaScript helpers consume the legacy envelope only; do not feed them a different layout as though it were the same schema.

`record_id, record_type, task_id, request_id, execution_id, sequence, previous_record_id, recorded_at, actor, schema_version, payload_json`

Envelope `schema_version` stays `connector-executor/1`; every Enforcer payload has `protocol: connector-enforcer/1`. Namespaced record types keep Executor readers compatible. Never use its generic `configuration`, `decision` or `run` types for Enforcer state. Enforcer `execution_id` contains a new stable review ID (e.g. `CE-…`), never an Executor execution ID. Order/predecessor groups follow the existing envelope: execution ID when present; otherwise type + request ID (or configuration). Reject duplicate IDs, unsupported protocols, incomplete JSON or broken sequence/predecessor. Optional checks live in `connector-enforcer/protocol.mjs`.

Read these minimal logical records:

| Type | Payload |
| --- | --- |
| `enforcer_configuration` | Exact board, active method/instruction entry point, manual designated writer, protected IDs, allowed report/fixture destinations, limits and profile references. Exactly one active configuration; explicit supersession requires a versioned migration. |
| `enforcer_profile` | Profile ID, human confirmer/time, each requirement ID/mode/text/source ID/exact quote, relationships and any confirmed standards with provenance. |
| `enforcer_request` | Frozen request ID, task/deliverable, Executor ID, draft ID, explicit version, enabled flag, explicit mode (`suggest_supported` for new V2 requests, `correct_supported` only when explicitly authorized, or `review_only`), requester/time, authorization, reviewer, method/instruction ID, accepted-source record IDs, profile ID; predecessor/reason for successor. Fixture requests additionally bind origin output and configured fixture ID. |
| `enforcer_run` | Protocol, review ID, stable key, complete frozen request, current phase and pointers to saved manifests/stages; known agenda/report IDs; suggestion plan/observation manifests, actual thread/reply IDs or unavailable-ID evidence; original completion evidence. Carry the same request every time. |
| `enforcer_blob` / `enforcer_manifest` | Bounded serialized snapshots/findings/patches/native batches/expected states/report candidate. Unique blob ID, indexed chunks, complete count/character count and ordered record-ID list. Manifest only after every chunk is read back exactly. |
| `enforcer_decision` / `enforcer_check` | Explicit recovery/new-attempt decision with actor/time/reason; separate invocation/acceptance evidence. Never overwrite original completion. |

Review key is board + task + deliverable + Executor execution + draft ID + review version. Request aliases do not create new work. Changing a frozen request blocks. One explicit higher version names its predecessor and human reason; preserve earlier reviews and reject competing successors.

For a new explicitly authorized disposable request, a request-scoped `enforcer_configuration` may overlay the single unchanged base configuration. Require exactly one overlay for that request, matching envelope request_id, `scope_request_id`, exact `base_configuration_record`, authorization actor/time/text, one allowed draft ID and the identical one-entry fixture list. Only runtime_owner, active_method, instruction_id, fixture_ids, allowed_draft_ids and projection_predecessor_review_id may be overridden; keep the base protected IDs, limits, board and destinations. Reject extra/duplicate/conflicting overlays. Other requests keep their original base configuration and completed provenance. This is a bounded writer grant, not an atomic lock or global ownership migration.

Discover fixture setup through `enforcer_check` records for the selected request. The fixture baseline record contains the exact seeded machine/native state before Work review; use it with the recorded origin and protected test passages. A projection_predecessor_review_id explicitly names the last owned Drafts K:M projection eligible to be replaced by this new test. Completed older requests return read-only and cannot roll that display back.

Read original Executor candidates/native prediction from their saved records. Register the accepted-source manifest from that execution rather than assembling a new arbitrary set. Resolve full source acceptance text, revision, approver/time and original evidence; compare with current native originals. A fixture's baseline is its recorded seeded machine text, not a hypothetical regenerated agenda. Save fixture origin and exactly what the test operator changed, separately from the baseline and any protected test note.

Frozen input manifest contains relevant task/dependency values and formulas, decision records, Executor request/context/baseline, accepted-source IDs and exact versions/text, profile/authorization, current native agenda/revision, comments/protection map and runtime ownership. All post-review stages point to this manifest. Keep source/task state separate from the agenda state changed by the correction itself.

Common phases: `captured → review_intent → findings_saved → candidate_saved`. Suggestion mode then uses `suggestion_intent → suggestions_pending_human_review`; explicit direct mode uses `edit_intent → edit_verified`. Both continue `report_candidate → report_create_intent → report_known → report_write_intent → report_verified → complete`. Clean/review-only paths skip candidate/publication phases. A suggestion publication retains outcome `suggestions_pending_human_review` even when its review/report is complete. It never records an accepted correction. Store `blocked`, `stale`, `needs_reconciliation` or explicit `closed` outcomes with last phase and known IDs; never discard effect intent. Before semantic work save attempt identity/intent, then actual result. Provider/thread/reply IDs are recorded only when exposed; unavailable IDs stay explicitly unavailable.

Save `suggestion_manifest` at intent and `suggestion_observations_manifest` after reloaded verification. The former contains the complete immutable proposal set, exact targets/context, finding markers, rationale, source support and original inventory; the latter contains actual pending state, controls, attached replies, observation time, IDs or screenshot/reply-count fallback. Partial publication retains each known thread and completed reply before attempting the next effect. These complete manifest references remain immutable for the review. Append progress/recovery observations separately; never replace an earlier effect identity. A completed repeat does not republish or add a reply. Human acceptance/rejection is a later decision, not permission to reopen.

Limits: 8 sources, 20,000 characters/source, 80,000 total source characters, 20,000 agenda characters, 8 patches/4,000 changed characters, 30,000 JSON characters/event, 240,000 characters/snapshot, 1,000 ledger events. Read bounded ranges, page complete discovery, and stop at limits instead of truncating required context. Split large values into ≤10,000-character chunks. Do not accept chunks without a complete matching manifest. Compare exact serialized chunk bytes on readback; optional hashes must name a deterministic algorithm, never an invented value.

Writes are literal stringValue cells, preserving the existing plain ledger structure and all older rows. On uncertain append inspect unique event IDs before retrying; conflicting/duplicate records stop. A Sheet batch is not a cross-service transaction or compare-and-set claim.

Enforcer owns only its namespaced append records, authorized agenda ranges, its one report and reserved Drafts K:M: `Review status`, `Review next step`, `Review report`. First inspect headers and all relevant cells/formulas/notes/validations/chips before reserving. Resolve Drafts row by Executor ID. Preserve A:J and its completion timestamp. Reject occupied/human-edited projection cells unless they exactly match the last owned projection. An old review cannot replace the latest visible version. Final outcome + owned projection may be one bounded Sheet batch. Tasks A–P, Reviews, ingestion/history/baselines and Executor outcomes remain read-only.
